# STAFF-UI: redesign of the staff side (admin + super admin) of "Зав байна" to an "operations dashboard" look in the public site's palette

Context: existing Next.js 15 (App Router) + Tailwind + Supabase app. Staff host = admin and super_admin screens. Backend (RLS, RPCs, MFA aal2, audit, hosts, consents) is DONE and must NOT change. Public/customer/worker screens must NOT change. This file is your memory with the repo and PROGRESS.md.

## 0. Rules for every session
- Do ONLY the phase named in the session prompt, then update PROGRESS.md ("Done: Tn", "Next: Tn+1", findings) and stop.
- Small context: read files in chunks of at most 150 lines, use search, never open a whole large CSS file, keep each file you write under ~300 lines, write COMPLETE files (no "...", no TODO).
- All UI text Mongolian Cyrillic in `src/lib/i18n/*` (code/comments English). Never print or commit secrets. No new npm packages (charts are plain SVG). No `dangerouslySetInnerHTML`. No fake or hard-coded data in production pages: real queries through the existing RLS-scoped helpers/RPCs, with skeletons and EmptyState. - This is a VISUAL redesign. Do not change tables, policies, RPC behaviour, auth, MFA, middleware or route paths. New DB objects are allowed ONLY as small SECURITY DEFINER aggregate functions (counts per day) that check `is_staff()`/`is_super()` first; run `npm run verify` after adding any.
- Files: put staff-only styles in `src/styles/staff.css` (or the existing staff stylesheet) and components in `src/components/staff/`; delete the previous staff shell, tokens and dead code after replacing them.
- After each phase run `npx tsc --noEmit` and `npm run lint`; run `npm run build` in T1, T3, T5, T8. Test on a production build (`npm run build && npm start`, one server on port 3000).

## 1. Look and feel (payments-operations dashboard reference)
A modern SaaS operations dashboard using the public Zav palette: paper `#F5F6F8`, white surfaces, ink `#0E1116`, and signal-lime `#C8F135` for selected and primary fills with ink foregrounds. The lime also tints active states and page-intro bands; links and focus indicators retain readable ink/outline contrast. Super admin keeps its separate violet accent (`#5B3DF5`). Status colours appear only on small pills (icon + text).

Typography: the site font (must render Ү/ү/Ө/ө), weights 400/500/600/700. The page title is 18/24 weight 600 and lives ONLY in the topbar; body 14px (16px on coarse pointers); section titles 15px; small uppercase labels 11px with letter-spacing .06em. No gradients other than the faint chart area fill; no decorative icons; no second title anywhere in the content.

## 10. Usability and accessibility rules (apply everywhere)
At most ONE black primary button per page header; at most TWO visible buttons per list row/card (the rest in "⋯"); button labels max 2 words / 22 characters; one purpose per page; destructive or irreversible actions use ConfirmDialog (dangerous ones also ReauthDialog); descriptions and notes `truncate` with title tooltip, full text only in detail views; visible focus ring (2px accent, 2px offset); everything keyboard operable; status never by colour alone; skeleton while loading, helpful EmptyState with one action; motion only transform/opacity <= 200ms (chart draw-in 600ms once); `prefers-reduced-motion` disables all movement; no horizontal page scroll (wide tables/boards scroll inside their own container); `scripts/check-density.mjs` (existing `npm run density`) keeps passing.
